# Архитектура проекта OneTake

## Технологический стек

*   **Язык программирования**: Python 3.10+
*   **UI Фреймворк**: PySide6 (Qt for Python). Выбран за нативную кроссплатформенность, широкие возможности работы с мультимедиа и стабильность.
*   **Запись видео/аудио**: 
    *   Планируется использование `ffmpeg` как внешнего процесса для надежного кодирования и сведения потоков, либо `OpenCV` + `sounddevice` + `ffmpeg-python` для более гранулярного контроля.
    *   Для первой версии: Захват экрана и камеры через нативные API или быстрые библиотеки (например, `mss` для экрана, `opencv` для камеры), сведение и сохранение через `ffmpeg` pipe.
*   **Управление настройками**: JSON файлы в пользовательской директории.

## Структура модулей

### `src/main.py`
Точка входа. Инициализирует `QApplication`, загружает конфигурацию и запускает `MainWindow`.

### `src/ui/`
Слой представления.
*   `main_window.py`: Основное окно приложения. Содержит навигацию между экранами "Библиотека" и "Подготовка".
*   `library_view.py`: Виджет списка записей.
*   `preparation_view.py`: Экран настройки перед записью.
*   `recorder_overlay.py`: Специальное прозрачное окно (overlay), которое отрисовывает рамку камеры и контрольной панели поверх всех окон во время записи.
*   `components/`: Переиспользуемые виджеты (кнопки, переключатели, индикатор уровня звука).

### `src/core/`
Бизнес-логика.
*   `recorder.py`: Управляет сессией записи. Запускает процессы захвата, следит за их состоянием, обрабатывает остановку и ошибки.
*   `audio_manager.py`: Отвечает за Enumeration аудио-устройств и получение данных для VU-метра.
*   `camera_manager.py`: Отвечает за захват превью камеры для UI.
*   `screen_capture.py`: Логика выбора монитора/окна (если требуется сложная логика).

### `src/utils/`
*   `config_manager.py`: Singleton для доступа к настройкам приложения.
*   `paths.py`: Утилиты для работы с путями (лог-файлы, папка с видео, временные файлы).
*   `ffmpeg_wrapper.py`: Обертка для запуска команд ffmpeg.

## Поток данных (Data Flow)

1.  **Инициализация**: При старте `main.py` загружает настройки через `ConfigManager` и инициализирует `MainWindow`.
2.  **Подготовка**: Пользователь меняет настройки в UI. `ConfigManager` обновляет состояние. `Preview` компоненты запрашивают видео/аудио потоки для отображения.
3.  **Запись**:
    *   Пользователь жмет REC.
    *   `MainWindow` сворачивается (или переходит в режим мини-контроллера).
    *   Появляется `RecorderOverlay` (камера).
    *   `Recorder` запускает процесс записи (FFmpeg), передавая ему параметры источников.
    *   Координаты окна камеры в `RecorderOverlay` отслеживаются и, в идеале, передаются в процесс записи (если реализуется динамическая компоновка на лету) или же (в MVP) камера пишется отдельным потоком/слоем, а позиционирование происходит программно. *Уточнение для MVP*: Самый надежный способ для "перемещения камеры" - это захват всего экрана, а камеру рисовать как top-most окно без рамок. Тогда она "запишется" сама как часть экрана. Это упрощает архитектуру до простого захвата экрана.
4.  **Остановка**:
    *   Пользователь жмет Stop.
    *   `Recorder` завершает процесс записи.
    *   Открывается `PreviewWindow` с записанным файлом.

## Решения для MVP

*   **Режим "Картинка в картинке"**: Реализуется через создание безрамочного окна поверх всех окон (`Qt.WindowStaysOnTopHint`). Это окно содержит изображение с веб-камеры. Программа записи захватывает экран целиком, включая это окно камеры. Это обеспечивает WYSIWYG и производительность без сложного пост-процессинга координат.
